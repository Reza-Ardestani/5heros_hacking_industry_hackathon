# AGENTS.md — Hackathon Project Operating Rules

1. Read `constitution/` and `organizer_docs/README.md` before planning or implementation.
2. Implement from the owning feature spec under `specs/features/` after its
   material product and technical decisions are settled. Drafts are planning artifacts.
3. Each feature spec contains exactly `requirements.md`, `plan.md`,
   `validation.md`, and `progress.md`; design narrative and diagrams stay separate.
4. Keep root progress brief; record detailed evidence in feature progress.
5. Preserve organizer documents verbatim. Record updated guidance and its source;
   ask organizers about conflicting eligibility or submission instructions.
6. Do not invent a chosen problem, approved stack, runtime commands, completed
   tests, organizer confirmation, or submission status.
7. Attribute starter code and datasets. Compare against a named baseline on
   equivalent inputs; clearly label synthetic scenarios and model assumptions.
8. Keep credentials and private participant data out of source, output, and screenshots.

Follow this repository's constitution. RadarCX supplies documentation structure,
not this project's database, integration, deployment, or product requirements.
